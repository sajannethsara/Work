### **Chapter 1: Introduction to Operating Systems**

An operating system (OS) is the software that provides the interface between the computer hardware and the users1. It is structured in a way that defines how its various components interact with one another2.

### **Section 1: Operating System Services**

The operating system provides a specific set of services to manage the computer and support user programs.

Key Services:

- **User Interface:** Almost all operating systems include a User Interface (UI) to allow interaction8.
    
- **Program Execution:** The OS handles loading a program, running it, and terminating it9.
    
- **I/O Operations:** It manages input and output devices10.
    
- **File System Manipulation:** This includes creating, deleting, reading, and writing files11.
    
- **Communication:** The OS enables communication between different processes (IPC)12.
    
- **Error Detection:** It is responsible for detecting errors and recovering from them13.
    
- **Resource Allocation:** The OS allocates resources such as the CPU, memory, and I/O devices14.
    
- **Security & Protection:** It controls access to the system to ensure safety15.
    

**Examples:**

- Windows provides services like a file explorer16.
    
- Linux provides shell-based services17.
    

A visual view of these services shows a hierarchy: users interact with the interface (GUI, batch, or command line), which sits above system calls, which then access the core services (like program execution and file systems) before reaching the operating system and hardware 18.

### **Section 2: System Calls**

A **System Call** acts as the interface between user programs and the operating system kernel19. When a program needs the OS to do something, it uses a system call.

**Categories of System Calls:**

- **Process control:** Examples include `fork` and `exec`20.
    
- **File manipulation:** Examples include `open`, `read`, `write`, and `close`21.
    
- **Device management**22.
    
- **Information maintenance**23.
    
- **Communication:** Examples include sockets and pipes24.
    

Example:

In the C programming language, the printf() function internally invokes the system call write()25.

Comparison: Windows vs. Unix System Calls

Different operating systems use different names for similar tasks26:

|**Category**|**Windows Example**|**Unix Example**|
|---|---|---|
|**Process Control**|`CreateProcess()`, `ExitProcess()`|`fork()`, `exit()`|
|**File Manipulation**|`CreateFile()`, `ReadFile()`|`open()`, `read()`|
|**Device Manipulation**|`SetConsoleMode()`, `ReadConsole()`|`ioctl()`, `read()`|
|**Information**|`GetCurrentProcessID()`, `Sleep()`|`getpid()`, `sleep()`|
|**Protection**|`SetFileSecurity()`|`chmod()`|

### **Section 3: Memory Hierarchy**

Computer memory is organized in a hierarchy based on speed and size.

Structure:

The order flows from Registers to Cache Main Memory to Secondary Storage27.

**Characteristics:**

- There is a tradeoff between speed and capacity28.
    
- **Registers** are the fastest but smallest29.
    
- **Hard Disks** are the slowest but largest30.
    

OS Responsibility:

The operating system manages memory across these different layers31. For example, the OS caches data that is used frequently in the RAM to speed up execution32.+1

### **Section 4: Interrupt Processing**

Interrupts are signals from hardware or software that require attention33.

**The Process Steps:**

1. **Interrupt occurs:** A signal is sent34.
    
2. **Save State:** The CPU saves its current state35.
    
3. **Transfer Control:** Control transfers to the Interrupt Service Routine (ISR)36.
    
4. **Resume:** After the ISR finishes, the CPU resumes its previous task37.
    

Examples:

Common interrupts include a keyboard press, the completion of an I/O task, or a timer interrupt38.

### **Section 5: OS Design & Implementation**

There are three main ways to design an operating system structure: Monolithic, Layered, and Microkernel 39.

#### **1. Monolithic Kernel**

In a monolithic system, all OS functionalities are bundled together into a single large kernel40. All services reside in kernel space41. The kernel runs entirely in kernel mode and has complete access to hardware42.

+2

- **Advantages:**
    
    - **High Performance:** There is less communication overhead because everything is in one layer43.
        
    - **Simplicity:** It is easy to design initially as one big program44.
        
    - **Direct Hardware Access:** Drivers run in kernel mode, which is good for speed45.
        
- **Disadvantages:**
    
    - **Difficult to Maintain:** A bug in one part can crash the whole OS46.
        
    - **Poor Modularity:** It is hard to add or remove features47.
        
    - **Security Risks:** A compromised driver can affect the entire OS48.
        
- **Example:** MS-DOS 49, Linux50.
    
    +1
    

#### **2. Layered Approach**

In this approach, the operating system is divided into a hierarchy of layers51. Each layer is built on top of the one below it52. A layer only interacts with the layer directly below it and provides services to the layer above it53.

+2

- **Advantages:**
    
    - **Modularity:** It is easier to understand and modify54.
        
    - **Ease of Debugging:** Problems can be traced layer by layer55.
        
    - **Security & Reliability:** Layers can enforce restricted access56.
        
- **Disadvantages:**
    
    - **Performance Overhead:** Requests may have to pass through multiple layers, making it slower57.
        
    - **Rigid Design:** Strict layering makes it hard to optimize performance if two distant layers need to communicate directly58.
        
- **Examples:** THE Operating System, Windows NT59.
    

#### **3. Microkernel Architecture**

A microkernel uses a minimalistic design60. Only the most essential functions run in kernel mode, while non-essential services (like file systems and device drivers) run as user-space processes61.

+1

- **Kernel Responsibilities:**
    
    - Low-level address space management62.
        
    - Thread and process management63.
        
    - Inter-Process Communication (IPC)64.
        
- **Advantages:**
    
    - Reliability & Stability65.
        
    - Security66.
        
    - Modularity67.
        
- **Disadvantages:**
    
    - Performance Overhead68.
        
    - Complexity of IPC69.
        
- **Examples:** Minix, QNX, Mach70.
